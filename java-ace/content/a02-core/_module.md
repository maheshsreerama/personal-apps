# Core Language Features
## Constructors
### [Constructors](lesson:a02-core/01-constructors)
- Same name as class, no return type, runs once on `new`
- `new` allocates + zeroes fields first; constructor starts with `super(...)` or `this(...)`
- Order: defaults → `super()` → field initialisers/instance blocks → body
- `void ClassName()` is a method, not a constructor
### [Default Constructor](lesson:a02-core/02-default-constructor)
- Compiler adds it only if you declare no constructor: `X() { super(); }`
- "Write one, lose the free one"
- Default ≠ no-arg: you write a no-arg; the compiler writes the default
- Same access as the class; parent without no-arg ctor breaks the child
### [Parameterized Constructor](lesson:a02-core/03-parameterized-constructor)
- Object is valid from birth; enables `final` fields
- `this.x = x` — without `this.` the field stays 0
- Validate + defensive copy, then assign
- Many params → Builder; same types → static factories
### [Copy Constructor](lesson:a02-core/04-copy-constructor)
- `X(X other)` — a convention, never generated by Java
- Primitives/immutables: copy; mutable fields: `new ...(other.f)` for deep copy
- Beats `clone()`: no cast, no checked exception, works with `final`
- Not polymorphic → use an overridable `copy()`
## Keywords
### [The this Keyword](lesson:a02-core/05-this-keyword)
- Reference to the current object; none in static code
- Uses: field, method, `this(...)`, pass, return (fluent), `Outer.this`
- `this(...)` first, no cycles, not together with `super(...)`
- Lambda `this` = enclosing object; anonymous class `this` = itself
### [The super Keyword](lesson:a02-core/06-super-keyword)
- Same object, parent's view — not a separate object
- Implicit `super()` in every constructor → parents first
- `super.method()` is non-virtual; `Interface.super.m()` resolves default clashes
- No `super.super`; never call overridable methods from constructors
### [The static Keyword](lesson:a02-core/07-static-keyword)
- Belongs to the class: one shared copy, no `this`
- Static methods are hidden, not overridden
- Static init runs once, lazily, thread-safely; constants don't trigger it
- `null` reference + static member = no NPE
### [The final Keyword](lesson:a02-core/08-final-keyword)
- Variable: assign once · Method: no override · Class: no subclass
- Final reference ≠ immutable object
- Constant variables are inlined by `javac`
- `final` vs `finally` vs `finalize()`; lambdas need effectively final
## Strings
### [Strings](lesson:a02-core/09-strings)
- Immutable, `final`; literals are interned in the string pool
- Compare with `equals()`, never `==`
- Every "modifying" method returns a new String
### [String Methods](lesson:a02-core/10-string-methods)
- `replace` is literal; `replaceAll`/`split`/`matches` use regex
- `split` drops trailing empty strings
- Java 11: `strip`, `isBlank`, `repeat`, `lines`
### [StringBuilder](lesson:a02-core/11-stringbuilder)
- Mutable, not synchronized; methods return `this`
- Capacity 16, grows to `2 * old + 2`
- Use in loops instead of `+=`
### [StringBuffer](lesson:a02-core/12-stringbuffer)
- Same API as StringBuilder, but `synchronized` methods
- Per-call thread safety only; compound actions need a lock
- Prefer StringBuilder unless truly shared
## Arrays, Enums & Wrappers
### [Arrays](lesson:a02-core/13-arrays)
- Fixed length, 0-based, elements get default values
- Arrays are objects: `length` field, `clone()` is shallow
- `java.util.Arrays`: `sort`, `toString`, `equals`, `fill`, `asList`
### [Enums](lesson:a02-core/14-enums)
- Fixed set of named constants; implicitly `final`, private constructors
- Can have fields, methods, constructors; `values()`, `valueOf()`, `ordinal()`
- Compare with `==`; great in `switch`; `EnumMap`/`EnumSet`
### [Wrapper Classes](lesson:a02-core/15-wrapper-classes)
- One wrapper per primitive; immutable and `final`
- Autoboxing/unboxing; unboxing `null` throws NPE
- `Integer` cache -128..127: `==` surprises, use `equals()`
